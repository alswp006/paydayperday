# Architecture Review
Generated: 2026-10-03T16:58:37.627Z
Score: 58/100

## Summary
The codebase is a small, mostly well-organized Toss mini-app with a clear split between pages, components and lib, and a sensible pure-function core (date, calculator, streak). It is weakened by two parallel data models (the real `BudgetSettings`/`RecordMap` model vs. the auto-generated `contract.ts` Budget/Transaction model), a haptic helper copy-pasted into 6 files, and inconsistent import and naming conventions. Several exported functions exist only to satisfy the generated contract and are used only by tests.

## Issues
### Critical
- [structure] Two parallel domain models coexist. The app actually runs on `BudgetSettings` / `DayRecord` / `RecordMap` / `AppResult` (types.ts, localStorage keys `ppd:settings`/`ppd:records`), while the generated contract (`Budget`, `Transaction`, `StreakData`, plus `calculateBudgetStatus`, `sumDailySpent`, `calculateDailyBudget`, `calculateCurrentStreak`, `useBudgetStore`, `normalizeNumberInput`) defines a different model with its own storage keys (BUDGET_KEY/TRANSACTIONS_KEY). The two persist to different keys, so the data never reconciles, and `useBudgetStore` writes data that no screen reads. `budgetStore.ts` mixes both APIs in one 286-line file. — Files: src/lib/contract.ts, src/lib/types.ts, src/lib/budgetStore.ts, src/lib/calculator.ts, src/lib/streak.ts / Fix: Pick the domain model the UI uses (BudgetSettings/RecordMap) as canonical. Delete the contract-only functions and `useBudgetStore`, or move them to a clearly labeled `src/lib/contract-adapters/` module if the contract must be satisfied. Update contract.ts (or stop treating it as authoritative) so it reflects reality.

### Warnings
- [duplication] The guarded haptic-feedback wrapper (try { Promise.resolve(generateHapticFeedback(...)).catch(() => {}) } catch {}) is re-implemented in at least 6 places under different names (fireHaptic, tick, haptic x3, inline in FloatingTabBar). Their type unions differ ('success'|'tickWeak', 'tickWeak'|'success'|'tickMedium', etc.), so behavior can drift. — Files: src/components/BottomCTA.tsx, src/components/ResultAdGate.tsx, src/components/SetupSheet.tsx, src/components/SpendInput.tsx, src/components/FloatingTabBar.tsx, src/pages/Home.tsx, src/pages/Result.tsx / Fix: Extract a single `haptic(type: HapticFeedbackType)` helper into `src/lib/haptic.ts` (or a `useHaptic` hook) and import it everywhere. Type the argument from the SDK's own type instead of hand-written unions.
- [duplication] Daily-budget math and the 'floor to 100 won' rule are implemented several times: `floor100` in calculator.ts, an inline `Math.floor(... / 100) * 100` in streak.ts `calculateCurrentStreak`, and the per-day success rule in `statusOf` vs. the spent-vs-limit check in `calculateCurrentStreak`. Two separate streak algorithms (`calcStreak` and `calculateCurrentStreak`) exist with different semantics (stored per-day budget snapshot vs. recomputed equal split). — Files: src/lib/calculator.ts, src/lib/streak.ts / Fix: Export `floor100` from one module and reuse it. Decide on a single streak definition; implement the contract-shaped function as a thin adapter over the main algorithm, or remove it.
- [dead_code] Several exports appear to be used only by tests or not at all: `calculateBudgetStatus`, `sumDailySpent`, `calculateDailyBudget`, `calculateCurrentStreak`, `useBudgetStore`, `normalizeNumberInput`, `formatCurrencyFn`-style contract types, `StreakData`, `AppInput`, `RouteState`, `cn`, and the `budgetStore` re-export of `normalizeDigits`/`toIntOrNull`. Unused components: `CountUp`, `MiniBar`, `Sparkline`, `FloatingTabBar`, `AdSlot`, `TossPurchase`, `EmptyState`/`LoadingState` (partly), `StreakData`. `budgetStore.ts` also imports `formatCurrency`, `nextPayday`, `toDateKey`, `addDays`, `computeDaily` (some are likely unused there). — Files: src/lib/calculator.ts, src/lib/streak.ts, src/lib/utils.ts, src/lib/types.ts, src/lib/budgetStore.ts, src/components/CountUp.tsx, src/components/MiniBar.tsx, src/components/Sparkline.tsx, src/components/FloatingTabBar.tsx, src/components/AdSlot.tsx, src/components/TossPurchase.tsx / Fix: Verify with a tool such as knip or ts-prune, then delete unused scaffold components and lib functions (or keep them in a template/ folder excluded from the build). Remove unused imports and the re-export of numberInput from budgetStore.
- [consistency] Two parallel ad-gating implementations: `TossRewardAd` (auto-unlocks on failure/timeout, with optional onLoadFailed/onDismissed overrides bolted on) and `ResultAdGate` (a state machine that wraps it and re-implements the failure UI). ResultAdGate's own comment admits the callbacks may not exist, so the contract between the two is implicit. `AdSlot` and `TossRewardAd` also read the ad ID differently (prop vs. env var in the wrapper). — Files: src/components/TossRewardAd.tsx, src/components/ResultAdGate.tsx, src/components/AdSlot.tsx / Fix: Make TossRewardAd a clear controlled primitive with explicit `onLoadFailed`/`onDismissed` callbacks and no auto-unlock default, and keep the policy in ResultAdGate. Centralize ad IDs in a `src/config.ts` that reads env vars once.
- [consistency] Inconsistent import path style and quoting. Pages and most feature components use the `@/` alias, while App.tsx, Amount, CountUp, ScreenScaffold and SummaryHero use relative paths (`../lib/utils`, `./pages/Home`). Scaffold components use double quotes while app code uses single quotes. Export style is mixed: named-only (Amount, Card), default-only (SetupSheet, SpendInput, TodayDashboard) and both (ResultAdGate, WeekStreak). — Files: src/App.tsx, src/components/Amount.tsx, src/components/CountUp.tsx, src/components/SummaryHero.tsx, src/components/ScreenScaffold.tsx, src/components/SetupSheet.tsx, src/components/ResultAdGate.tsx, src/components/WeekStreak.tsx / Fix: Standardize on the `@/` alias and named exports (pages may stay default for lazy loading), and enforce quotes and import style with ESLint/Prettier.
- [consistency] Error-handling is inconsistent in the storage layer. `storage.getItem` swallows JSON errors and returns null, `setItem` throws, and `budgetStore.read()` then re-reads `localStorage` directly to detect corruption, bypassing the storage abstraction. Many bare `catch {}` blocks silently swallow errors in ad/IAP/haptic wrappers. Save operations return `SaveResult`, whereas `useBudgetStore` methods are async and throw. — Files: src/lib/storage.ts, src/lib/budgetStore.ts, src/components/AdSlot.tsx, src/components/TossPurchase.tsx / Fix: Make `storage.ts` return a discriminated result (`{ok, value}` or `{broken}`) so budgetStore does not need to reach around it. Use a single error convention (Result type) for persistence. Log swallowed errors in dev.

Storage-key prefix `ppd:` is opaque. — Files: src/components/BottomCTA.tsx, src/components/StateView.tsx, src/pages/__TdsGallery.tsx, src/lib/contract.ts / Fix: Rename files to match their primary export (e.g. `SubmitFooter.tsx`, split `EmptyState.tsx`/`LoadingState.tsx`) or add an index barrel. - [structure] Business logic and orchestration live in page components: Home and Result both load the store, call computeDaily, weekStatus and calcStreak, and assemble an `AppResult` (duplicated block). Cross-layer coupling: `budgetStore.ts` imports from calculator and date while also owning persistence; `types.ts` contains a runtime constant (STORAGE_KEYS) alongside pure types. Move STORAGE_KEYS to storage/budgetStore. Split `components/` into `ui/` (generic primitives) and `features/` (SetupSheet, SpendInput, TodayDashboard, WeekStreak, ads).
- [circular_dep] No true import cycles are visible, but there is a latent one: types.ts is imported by date.ts, calculator.ts and streak.ts, and budgetStore.ts imports all of them plus contract and types. Tests import `numberInput` helpers through the budgetStore test file, blurring module boundaries. Keeping runtime values (STORAGE_KEYS) in types.ts raises the risk that a future import from types.ts into lib code creates a cycle. — Files: src/lib/types.ts, src/lib/budgetStore.ts, src/lib/budgetStore.test.ts / Fix: Keep types.ts type-only, put constants in a separate `constants.ts`, and move the numberInput tests into their own `numberInput.test.ts`.
- [consistency] Tests are organized inconsistently: `logic.test.ts` covers calculator and streak, `budgetStore.test.ts` also tests numberInput, and there are no component or page tests. Test files are co-located with source in `lib/`, which is fine, but the names do not match the modules under test. — Files: src/lib/logic.test.ts, src/lib/budgetStore.test.ts / Fix: Split into `calculator.test.ts`, `streak.test.ts`, `numberInput.test.ts`, `budgetStore.test.ts` so each test file mirrors one module.
